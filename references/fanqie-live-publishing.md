# 番茄线上上传与章节修订

用户要求登录番茄上传小说或短故事、设置定时发布、提交审核，或者修复已经上传正文中的分场符和格式问题时读取本文件，并同时读取 [platform-delivery-quality.md](platform-delivery-quality.md)。平台页面和规则会变化，先检查当前页面；本文件规定的是授权边界、数据不变量和恢复方法，不把某次作品 ID、章节 URL 或页面选择器当作永久事实。

## 权限与真源

- 番茄网页中的作品是外部发布副本，Markdown 正典仍是唯一主稿。普通排版修复只有在能够证明非空正文逐段不变时才允许直接在线处理；涉及措辞、标题、剧情或段落内容的修改必须先回到正典，完成受控改稿、重新导出后再发布。
- 登录、查看列表和只读核验不等于获得上传或提交授权。实际上传、覆盖正文、提交审核、修改排期或接受作品/封面相关协议前，必须让作者确认具体作品、章节范围、动作和目的；当前浏览器工具若要求操作时确认，按其规则执行。
- 一次批量确认只覆盖确认单中列明的作品、章节范围、排除章节、正文变换、AI 使用声明和发布方式。新增章节、改变标题/分卷/排期、签约、收益设置、删除章节或扩大范围都需要新的确认。
- 线上操作本身不修改项目正典，因此只要本地文件不变就不取得项目写入租约；仍需先执行 `work-ensure`，并避免多个窗口、Agent 或人工同时编辑同一本线上作品。

## 上传前确认单

只从通过项目验证、连续性与质量双门禁，且 `novel_export.py status` 同时返回 `status: fresh`、`delivery_quality: pass` 并包含 `fanqie-serial` 或 `fanqie-short-story` 目标配置的番茄包上传。`novel_continuity.py status` 必须为 `current`，`novel_review.py status` 不得有到期审核；`baseline_required`、`review_due`、`stale`、开放失效项或未通过报告都会阻断。旧清单、通用纯文本配置或只通过文件哈希的包都不能冒充番茄已验证包。开始前建立可核对的章节清单，至少包含：

- 项目与作品名称、平台作品 ID 或当前作品页面。
- 章号、标题、番茄正文文件、正文哈希和目标字数。
- 分卷、AI 使用声明、立即发布或定时发布的绝对日期与时间。
- 本次包含的章节和明确排除的章节。
- 封面、简介、标签或协议是否在授权范围内；未列明的字段不顺手修改。
- 本地正典哈希、当前连续性基线、最新质量审核和导出清单哈希；四者必须属于同一版正文。

番茄包中的独占 Markdown 分场线已经在导出时派生为空行。上传前由 `status` 重新执行严格 UTF-8、无 BOM、LF、NFC、危险/不可见字符、Markdown/HTML 残留、文件名、文件库存、首末章、标题映射和正典派生字节检查；独占分场线计数必须为零。正文行内出现的 `* * *` 是普通文字，不能删除。

## 逐章上传

每章按清单串行处理并留下明确检查点：

1. 进入目标作品和章节，核对章号、标题与分卷，不能只凭当前打开的标签页推断作品。
2. 从对应番茄导出文件填写正文，填写后重新读取编辑器段落并与输入逐段比较。
3. 打开发布设置，核对章节标题、分卷、AI 使用声明、发布方式、日期和时间。任何字段与确认单不一致时停止，不能以平台默认值代替作者选择。
4. 提交后要求出现成功提示或返回该作品的章节管理页，并记录章节号和结果；没有权威成功信号时状态记为不确定，不能直接重复提交。
5. 批量任务按小批次推进。每章都必须形成“正文已校验”和“提交已确认”两个独立检查点，避免长脚本中断后无法判断边界。

## 已上传正文的分场符修复

先从章节管理页读取目标章节当前标题、状态、发布时间和编辑入口，形成不可扩张的修订清单。只删除独占整个段落的约定分场标记。对于 `* * *`，使用段落级判断：

```js
const marker = /^\s*\*\s+\*\s+\*\s*$/;
const original = await editor.locator("p")
  .evaluateAll(paragraphs => paragraphs.map(p => p.innerText));
const target = original.filter(text => !marker.test(text));
```

不能使用全文字符串替换，因为它会误删引号、对白或说明中的行内 `* * *`。执行替换前后遵守以下不变量：

- 修改前的匹配数量必须等于修订清单记录的预期数量；数量为零或异常时先判断是否已经处理、页面未加载完整或源稿不同，不能继续覆盖。
- 用段落间空行连接 `target`，让分场位置保留自然空行，不插入可见星号或新的装饰符。
- 替换后独占分场标记必须为零。去除文末空白段后，编辑器中的每个非空段落必须与 `target` 同位置完全一致；只允许平台对末尾空白做规范化。
- 章节身份必须始终与修订清单一致。正文校验通过后才点击“下一步”。
- 发布设置必须保持原章节标题、分卷、已确认的 AI 使用声明以及原发布状态和绝对时间。格式修复不是改名、改卷或重新排期的授权。
- 提交后必须返回章节管理页或出现权威成功提示，才把该章记为完成。

番茄编辑器可能要求正文区域获得真实焦点后才能替换。应先用当前可见 DOM 找到正文编辑器和一个可见的普通长段落，再点击文字区域并确认编辑器进入聚焦状态；不要依赖未经核验的固定坐标。当前页面常见的主编辑器是第一个可见 `[contenteditable="true"]`，但必须同时用章号和标题输入框校验身份，页面结构变化时重新定位。

## 超时与中断恢复

导航、自动保存和提交超时都属于未知结果，不是失败证明。发生中断后先重新连接作者指定的浏览器，通过最新的打开标签页列表认领精确标签页；不能猜测标签页 ID，也不能立即重复点击。按可见状态恢复：

- 已回到章节管理页，且行状态/成功提示与清单一致：该章完成。
- 编辑器中分场标记为零且发布设置仍打开：重新核对设置后，只完成剩余提交步骤。
- 编辑器中分场标记为零、没有发布设置：核对“已保存”和正文差异，再从“下一步”恢复。
- 分场标记仍等于修订前预期数量：说明正文替换未生效，可以重新执行该章。
- 标记数量既不是零也不是预期值，或任一非空段落不同：立即停止并报告，不自动修补或继续下一章。

浏览器控制应把导航/正文替换校验与发布设置/提交拆成可恢复阶段。可以由外层协调器顺序处理小批次，但同一作品任何时刻只允许一个线上写入者；不得为了提速并行提交多章。

## 最终审计

批量操作结束后同时验证本地包和线上列表：

1. 本地运行 `novel_export.py status`，要求为 `fresh`、`delivery_quality: pass`，并核对目标番茄配置、文件数和独占分场线计数为零。
2. 再核对 `novel_continuity.py status` 仍为 `current`、质量审核仍未到期；上传过程中本地主稿或审计状态变化时停止剩余章节，重新生成确认单。
3. 逐页读取章节管理列表，目标章节数量必须与确认单相同；逐章比对标题、状态和绝对发布时间，结果必须零差异。
4. 明确核对排除章节仍保留原标题、状态和时间。
5. 重新打开首个、范围边界、中间样本、最后一个以及所有曾经中断的章节，确认独占分场标记为零；抽查不能替代每章提交前的完整正文校验。
6. 记录目标章数、实际提交章数、删除的分场标记总数、失败或不确定章号和仍待平台审核的状态。不能只报告“批量完成”。
7. 完成后把浏览器留在对应作品的章节管理页，便于作者复核。

平台审核、发布时间展示和页面字段可能随规则更新而变化。遇到当前页面与本文件示例不同，保留上述授权和数据不变量，依据可见页面重新定位，不复用过期 URL、作品 ID、章节 ID 或选择器。
