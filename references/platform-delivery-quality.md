# 平台交付质量闸门

生成 TXT、DOCX、EPUB、番茄长篇分章包、番茄短故事单文件或其他待上传文档时读取本文件。目标不是宣称第三方平台永远不会改变规则，而是让每个已实现的导出配置都有可重复的本地验证证据；任何必需检查未通过时，不生成或交付正式上传包。

## 适配边界

| 配置 | 当前用途 | 已验证的关键约束 |
|---|---|---|
| `generic-plain-text` v1 | 可移植纯文本、合并阅读稿、未知平台的安全起点 | 严格 UTF-8、无 BOM、LF、NFC、无危险或歧义 Unicode、无 Markdown/HTML 残留、正文与正典派生结果完全一致 |
| `fanqie-serial` v1 | 番茄长篇逐章正文 | 纯正文、标题仅在文件名、独占分场符为空行、章节与文件一一映射 |
| `fanqie-short-story` v1 | 番茄短故事单文件正文 | 单篇纯正文、标题仅在文件名、独占分场符为空行、不得带技术性章号 |
| `docx-review-package` v1 | Word 审阅稿 | ZIP 与必需部件完整、XML 可解析、正文 Unicode 合法、章标题数量正确、正典正文无缺失 |
| `epub3-reading-package` v1 | EPUB 阅读版 | EPUB mimetype、ZIP、OPF、导航、NCX、章节 XHTML、Unicode 和正典正文覆盖均通过 |

`generic-plain-text` 只保证通用文本安全，不代表已经核验某个未实现平台的标题字段、字数限制、分卷规则、内容政策或上传接口。用户指定新平台时，先查看该平台当日公开规则和当前上传页面，再新增或选择明确的平台配置；未知平台不能被写成“已适配所有平台”。

## 失败关闭流程

1. 从 `novel.json`、`manuscript/index.md` 和索引指向的已提交 Markdown 读取源快照。
2. 先执行源文本 Unicode 闸门。发现有歧义的字符立即报出文件、码位和位置，不进入正式包构建。
3. 只在内存和临时导出目录中进行安全、可追溯的派生规范化，不反向写入 Markdown 正典。
4. 对每个临时文件重新按字节读取；文本严格解码，DOCX/EPUB 重新打开并检查内部结构与正文覆盖。
5. 源快照再次校验不变后，才替换清单管理的旧派生文件；质量失败不得覆盖已有有效包。
6. 最后写入 `export-manifest.json`。没有 `delivery_quality.status: pass` 和正确平台配置的旧清单，不算已认证上传包。

## Unicode 与编码规则

允许自动规范化并在清单中计数的项目只有：

- CRLF 或 CR 换行为 LF。
- Unicode 规范化为 NFC；不使用会改变字符兼容形态的 NFKC。
- Tab、NBSP、窄不换行空格、全角空格和已列明的排版空格转换成普通 ASCII 空格。
- 删除行尾 ASCII 空格，并确保文件末尾恰好一个 LF。

以下情况失败关闭，不静默删除或猜测替换：

- 文件开头或正文中间的 BOM、`U+FFFD` 替换字符、NUL、非法 C0/C1 控制字符。
- 双向文本控制符、私用区字符、未分配码位、Unicode 非字符、孤立代理项。
- 零宽空格、软连字符、对象替换符等歧义不可见字符。
- 孤立的变体选择符、连接控制符或不完整的 Emoji tag 序列。
- Unicode 行/段分隔符等可能被不同平台解释成不同结构的字符。

正常中文标点、全角标点、扩展区汉字、组合后合法的文字、常见 Emoji、Emoji ZWJ 序列和合法变体序列必须无损保留。私用区字符常来自网页自定义字体映射；不能凭字形猜回原字，应回到权威页面、原始数据或作者主稿确认后再修正正典。

## 纯文本包规则

每个 TXT 在临时目录和 `status` 检查时都必须满足：

- 字节可用严格 UTF-8 解码，任何位置都没有 BOM，换行只有 LF，字符串已是 NFC。
- 没有 Tab、非标准横向空白、行尾空格、连续两个以上空白行或多余文末空行。
- 不为空；任一单行超过 20000 字符时阻断。该数值是异常结构防护，不是平台字数规则。
- 没有 Markdown 标题、代码围栏、链接、图片、成对强调标记或 HTML 标签残留。
- 文件名为 NFC，不含 Windows 非法字符、设备保留名、尾随空格/句点、路径穿越或超长片段。
- 从当前正典重新派生的规范化字节与实际文件完全相同，不能只依赖清单中的旧哈希。

番茄配置另外要求：

- 长篇每个索引章恰好对应一个 `fanqie/NNNN-标题.txt`；短故事恰好对应一个 `fanqie-short-story/《故事名》.txt`。
- 正文不重复携带平台标题或技术性章号，标题由文件名映射到平台标题字段。
- 独占一行的 `---`、`***`、`* * *`、`___` 等分场线派生为空行；对白或说明中的行内 `* * *` 原样保留。
- 章节数、升序、首末章、标题映射和源哈希都与 `manuscript/index.md` 一致。

## 清单与状态

`export-manifest.json` 至少记录：

- 源快照、每章源哈希、章节顺序和源到派生的规范化计数。
- 编码、换行、Unicode 规范化形式、失败策略和质量验证时间。
- 每个文件的路径、格式、字节数、SHA-256、平台配置名称与版本、检查结果和实际规范化计数。
- 本次用到的平台配置完整定义；兼容范围固定为 `verified_profiles_only`。

`novel_export.py status` 必须重新读取实际文件并执行质量检查，不能只比对哈希。结果解释：

- `blocked`：连续性、质量审核或项目有效性门禁未通过、到期或过期；不得导出或上传。
- `fresh`：正典快照一致、文件库存一致、所有质量报告仍有效且实际复检通过。
- `stale`：文件包自身未发现异常，但正典已经变化，必须重新导出。
- `modified`：文件、清单、平台配置、质量报告或目录库存存在差异；不得上传。
- `missing`：没有导出清单，尚未形成正式包。

`exports/` 中出现不在清单内的文件时，状态为 `modified`，导出器也停止。不要自动删除这些文件；先确认其用途并移到派生包之外，避免把 `Thumbs.db`、临时稿、旧封面或其他未知文件一起上传。

## 交付与新平台

交付上传包前，至少运行：

```powershell
python -X utf8 .\scripts\novel_export.py export "<project-root>" --format fanqie
python -X utf8 .\scripts\novel_export.py status "<project-root>"
```

只有 `status: fresh`、`delivery_quality: pass` 且 `verified_profiles` 含目标平台配置时，才能把对应目录称为可上传包。DOCX 仍需实际逐页渲染检查，EPUB 有条件时再运行 EPUBCheck；自动包结构校验不能替代视觉检查。

新平台接入时，先确认标题是否单独填写、正文是否允许章标题、编码、换行、分场符、文件数量、单章/全篇长度、卷章映射和支持的文档类型。新增确定性配置与真实测试后才标记为已验证；在此之前只生成 `generic-plain-text` 安全稿，并明确列出仍待平台核验的字段。
