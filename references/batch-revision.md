# 全本机械改稿规程

本文件用于跨章节的确定性文本变换，例如统一破折号、降低重复口癖或按规则调整句式。它不是“全文替换快捷方式”：任何会改变正典文件的批量操作都必须可回滚、可核对、可重新绑定审核证据。

## 适用边界

- 只处理已经明确的机械症状和允许变换；涉及事实、剧情、人物动机、关系、世界规则、POV 或章节顺序时，改走 [revision.md](revision.md) 的影响图并请求作者裁决。
- 先列出文件清单、旧 SHA-256、变换规则、豁免项、预期计数和允许的最大差异。没有基线或无法解释的计数变化时停止。
- 正文真源仍是 `manuscript/chapters/*.md`。工作中的候选写入当前 `work-root` 或 `staging/`，不把工作目录快照当成新的正典。

## 执行顺序

1. 在工作目录建立本会话快照，例如 `revisions/snapshots/<timestamp>/`，保存原始字节、文件清单和快照哈希。快照只表示“本次改动前状态”，不能代替 Git、项目备份或已提交正典。
2. 对每一章生成候选副本，使用结构化文本读取和明确的逐项规则。禁止对整本书做未经豁免的 `replace()` 或正则全局替换。
3. 对跨章频率问题使用确定的分布策略（例如按章节序号取模轮换），把规则版本、种子/序列、每章计数和未处理项写入机器可读报告；同一输入和规则必须可重现。
4. 对破折号、分场线、引号等高风险符号先做豁免扫描：对白、专名、代码/引用、已确认时代语言、行内 `* * *` 和作者明确保护的段落不进入替换集合。豁免项数量必须记录，不能用“替换后看起来正常”代替核对。
5. 对口癖、连接词和机械排比分别统计变换前后频次。下降过快、某章归零、单一替代词异常集中或人物口吻被抹平时停止并回滚该批次。
6. 对数字、日期、金额、章节号、年龄、距离、时间债务等数字锚逐字比对。任何锚点增删或上下文改变都视为语义变化，必须进入连续性影响图，不能由批处理器自动决定。
7. 每个实际变化的章节都重新调用 `$humanizer-zh` 做逐章自然化复核，并保存 `chapter-before-humanizer.md`、最终结果和哈希绑定审阅记录。Skill 不可用时只保留候选，不得进入正典。
8. 对候选逐章重跑结构/连续性/原创性检查；若正文哈希变化，旧的连续性审计、原创性报告和质量报告全部失效，不能只改报告中的哈希字段。
9. 取得项目租约并通过 `write-check` 后，按项目既有受控改稿协议写回。写回完成后严格按以下顺序执行：

   `prepare-baseline` → 独立全局连续性复审并完成报告 → `record-baseline` 封存通过报告 → 独立影响范围质量复审 → `novel_export.py status` 与重新导出。

   `record-baseline` 只能记录已经完成且结论为 `pass` 的独立报告，不能在复审前先封存。任一步未通过都停在工作目录，不能导出或上传。

## 质量报告最低字段

```json
{
  "rule_version": "dash-normalization-v1",
  "snapshot_sha256": "改动前快照哈希",
  "files": [
    {
      "path": "manuscript/chapters/0007-title.md",
      "before_sha256": "...",
      "after_sha256": "...",
      "changed": true,
      "counts": {"candidate": 12, "replaced": 8, "exempt": 4},
      "numeric_anchors_before": ["第七日", "1200元"],
      "numeric_anchors_after": ["第七日", "1200元"]
    }
  ],
  "rollback_path": "revisions/snapshots/20260912T120000Z",
  "status": "ready_for_independent_review"
}
```

报告中的“无变化”也要有前后哈希，不能把未处理文件混入已完成清单。发现计数漂移、锚点差异、无法解释的段落变化或核心设定影响时，状态设为 `blocked`，保留候选和快照并回到作者裁决。
