# 审稿与系统改稿

跨章节的确定性批量文本变换另读 [batch-revision.md](batch-revision.md)。它规定快照、豁免扫描、频次/数字锚验证，以及“基线记录 → 独立复审 → 重新导出”的顺序；不能把单章润色流程直接扩大为全本替换。

在章节评价、全文诊断、查错、重写或润色任务中读取本文件。用户只要求分析时保持只读。

## 先诊断层级

按由外向内的顺序判断问题，不要在结构仍坏时先做句子美容：

1. **概念层**：故事承诺、主题问题、人物欲望与结局是否相容。
2. **结构层**：因果链、升级、转折、高潮、信息释放和节奏。
3. **场景层**：目标、阻力、策略、选择、变化和 POV。
4. **文风层**：声音、句式、意象、对话、叙述距离和冗余。
5. **校对层**：错别字、标点、格式、称谓和可机械修复的问题。

上层问题会使下层修改失效。一次审稿可以覆盖多层，但修订计划必须标出先后依赖。

## 审稿报告

每条发现使用以下字段：

```text
严重度：阻断 / 重要 / 一般 / 建议
位置：章节、场景或短引文
问题：可验证的具体描述
影响：它如何损害因果、人物、节奏、理解或声音
修法：最小可行修改；必要时给另一种取舍
影响范围：局部 / 后续数章 / 全书
作者判断：是否涉及偏好或正典裁决
```

先列高影响问题。没有证据的问题写成疑问或偏好，不包装成客观错误。若没有明显问题，明确说明并指出仍未覆盖的风险或阅读范围。

审稿分为两份互不替代的机器可读报告：

- [continuity.md](continuity.md) 只检查因果、时间、地点、人物状态、知识边界、关系称谓、物品数值、世界规则和伏笔回收。确定矛盾阻断；疑似误导或有意例外作为警告并保留证据。
- [periodic-review.md](periodic-review.md) 只检查钩子、节奏、张力、人物弧、文风、原创表达、平台适配、自然度和语言格式。`blocker` 对应 `block`，`important` 对应 `needs_revision`。

两类报告都绑定源快照。已审核正文、状态增量或正典发生变化后必须重新审核，不能沿用旧结论或只手改报告哈希。

## 改稿影响图

重大修改前写清：

- 修改属于概念、结构、场景还是文风层。
- 当前稳定状态和要解决的明确症状。
- 对接下来 1-2 章、3-5 章和全书结局的可能影响。
- 必须同步更新的人物动机、伏笔、时间线、世界规则、章节索引、章节记忆卡和后续台词。
- 成功信号、回滚信号和恢复点。

先用依赖图计算传播范围：

```powershell
python -X utf8 .\scripts\novel_continuity.py impact "<project-root>" --changed-path "manuscript/chapters/0012-title.md" --change-type timeline
```

局部事实、人物状态、知识、时间和线索修改按事实与章节依赖闭包扩散；世界规则、人物命运、核心关系、核心真相或边界不明的修改，从最早受影响章起重审全部后续章节。核心变化不采用“看起来只影响这一段”的乐观判断。

先做能验证假设的最小改动。一个人物动机变化可能影响所有选择场景，不能只改首次介绍段落。

## 执行顺序

1. 在工作目录准备方案；涉及已提交正文时保存原文快照或确认已有版本控制。
2. 确定问题和影响图。普通小错可在隔离暂存区自动修复；核心设定、人物命运、重要关系、世界规则和重大伏笔必须询问作者。
3. 作者批准后取得项目租约并运行 `write-check`，使用 `novel_continuity.py invalidate` 登记受影响范围，使续写、导出和上传先进入阻断状态。
4. 修正最高层问题，并按依赖顺序修改全部受影响章节，不顺手扩大范围。
5. 更新故事圣经、大纲四态、相关章节记忆卡、章节索引、当前状态、时间线、事实库、例外库和线索账本；重大追溯修改记录到 `memory/decisions.md`。
6. 对受影响范围重新做全局连续性基线；如果存在确定重大冲突，按人物/时间线/物品数值/核心规则/伏笔关系分批询问，不擅自封存。
7. 若改稿改变措辞来源风险或故事核心结构，更新原创性计划并按 [originality-audit.md](originality-audit.md) 重跑双层审计；再独立重跑质量审核。
8. 运行项目验证、重建或更新 SQLite 派生索引，并输出变更摘要、剩余问题和恢复位置。全部通过后重新导出；线上版本必须另列清单并再次确认，不能因本地已批准就自动覆盖。

## 场景与文风修订

场景问题优先改目标、阻力、选择和结果。文风问题再处理解释过度、重复信息、视角漂移、对话同质、意象堆叠和节奏单一。只做局部修订时不要改变原段落的事实、语气与隐含关系。

“去 AI 味”是末轮检查，不是改稿目标本身。可以删除元话语、空泛总结和机械排比，但不能因此抹掉人物口癖、主题复沓、时代语言或叙述者偏见。

## 停止条件

- 请求范围内的高影响问题已解决并重新验证。
- 继续修改只会改变作者偏好，而不是修复已确认问题。
- 修订开始在不同层之间来回制造回归；此时回到影响图或恢复点。
- 达到用户指定的篇幅、时间或轮次边界。

不要无限润色，也不要为了提高自创分数反复重写。最终交付应让作者知道哪些问题已修复、哪些取舍被保留、哪些变化仍需全书级同步。
