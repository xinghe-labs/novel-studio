# 复盘蒸馏（retrospective）

在以下时机读取本文件并执行一次复盘蒸馏：①周期质量审核完成并裁决后（见 [periodic-review.md](periodic-review.md)）；②一次大轮次（批量修订、全书补拍、基线重封、导出交付）完成后；③短故事完稿审核后；④作者点名复盘时。复盘的产出不是报告，是**回写**：每一条发现必须落成可执行规则、书级配置、正典裁决请求或管线记忆——落不进这四样的发现不算数。

## 三步

1. **汇集**：扫本轮全部产物——审稿 findings、批量校验的失败项与豁免、签名账变动、管线报错与绕行、作者裁决记录。只收有证据的发现，不收感觉。
2. **分类**（四桶，逐条归桶）：
   - **A 法则缺口**：暴露 anchor-discipline 或其他 reference 的口径、清单、规程缺口 → 写成补丁候选（条款级修改建议＋证据），进裁决队列的 skill 补丁段；
   - **B 书级变通**：只对本书成立的口径与判例 → 当场回写本书 `voice-anchor.md` 的「本书特有变通」或 `style-guide.md`，不入法则；
   - **C 正典裁决**：需要作者拍板的正文问题（矛盾、引文异文、体例、重构）→ 进裁决队列（workspace 根 `adjudication-queue.md`），条目带位置、逐字证据、两个以上选项与建议；
   - **D 管线坑**：脚本、平台、校验器的坑与绕行 → 写入项目记忆或跨会话记忆卡，附复现条件。
3. **回写**：B、D 当场完成；A、C 进队列等作者裁决。裁决后的回写纪律：skill 补丁在下一次发版落地，正典修订在下一轮受控修订落地，落地后在队列中销账——销账记录（改了哪个文件哪一条）写回条目本身，不删条目，保留审计轨迹。

## 裁决队列

- 位置：workspace 根 `adjudication-queue.md`，本地 git 管理，永不上传。
- 条目 schema：编号（YYYYMMDD-序号）｜书｜来源（哪轮哪审）｜位置与逐字证据｜选项与建议｜状态（`open`／`adjudicated`／`written-back`／`obsolete`）。
- 每次 commit-chapter、导出或大轮次前扫一遍 open 项：会阻塞本次动作的（基线闸门、导出口径、体例闸门）先解决；不阻塞的保持挂账，不积压成隐性债务。
- 作者裁决方式：逐条选项拍板或整段授权；无裁决的 open 项不自动过期。

## 学习边界

- **学习速率＝写作速率**：法则进化需要新证据，证据只能来自正文；没有新正文的复盘不产生 A 类发现。
- **审美裁决归作者**：什么算「长在戏上」、复沓是否有意、异常是否伏笔——agent 判例是概率性的，会误判，裁决层不可自动化。
- **跨书升格门槛**：单书证据只进 B（书级变通）；同一发现获得两本书验证才升格为 A（法则候选）。跨书复盘在 ≥2 本书各自完成一次大轮次后执行，把共性发现蒸馏成法则候选。
- **冷启动修订**：新书 voice-anchor 配置层在大纲期立初版即可（彼时只有大纲没有后见之明），第 3 章提交后按实际正文修订一次——这是流程债，不要试图一次写对。
